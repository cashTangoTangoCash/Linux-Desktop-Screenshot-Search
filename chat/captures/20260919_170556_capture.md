That is actually an intentional safety mechanism in Org mode!

In Org mode, any line starting with a literal `*` in column zero—even inside a `#+BEGIN_EXAMPLE` block—can still break Org parser structures, `org-element` queries, outline folding, or agenda indexing depending on your installed Org version and hooks.

To prevent raw text from corrupting document structure, Org mode uses **comma-escaping**: any line beginning with a star `*` or hash `#` inside a block gets escaped by prepending a comma (`,*` or `,#`). When Org renders or exports the block, it automatically strips that leading comma, leaving the visual output intact while keeping the Org parser 100% happy.

Replacing `* ` with `*, ` works, but it permanently modifies your OCR text. Prepending a comma (`,*`) follows native Org mode conventions.

Here is the updated `write_log` function that automatically applies comma-escaping to any lines starting with `*` or `#` in the OCR text:

```python
def write_log(effort_dir: Path, query_label: str, sql: str, matches_data: list[dict]):
    """Writes or overwrites README.org inside the effort directory with embedded OCR text."""
    log_path = effort_dir / "README.org"
    now_str = datetime.datetime.now().strftime("%Y-%m-%d %H:%M:%S")

    lines = [
        f"#+TITLE: Screenshot Search: {query_label}",
        f"#+DATE: [{now_str}]",
        "#+CATEGORY: effort",
        "",
        "* Search Metadata",
        f"- **Query / File:** ~{query_label}~",
        f"- **Executed At:** {now_str}",
        f"- **Matches Found:** {len(matches_data)}",
        f"- **Database Used:** ~{DB_PATH}~",
        "",
        "* SQL Executed",
        "#+BEGIN_SRC sql",
        sql.strip(),
        "#+END_SRC",
        "",
        "* Matched Items",
    ]

    for item in matches_data:
        idx = item["idx"]
        path_str = item["orig_path"]
        url = item["url"]
        ocr_text = item["ocr_text"]
        img_symlink = item["img_symlink"]

        lines.append(f"** Match {idx:03d}: [[file:{img_symlink.name}][{img_symlink.name}]]")
        lines.append(f"- **Original Path:** ~{path_str}~")
        if url:
            lines.append(f"- **Source URL:** {url}")
        
        lines.append("")
        lines.append(f"*** OCR Text for Match {idx:03d}")
        if ocr_text:
            lines.append("#+BEGIN_EXAMPLE")
            # Comma-escape lines starting with '*' or '#' to protect Org parser
            escaped_ocr = []
            for line in ocr_text.splitlines():
                if line.startswith("*") or line.startswith("#"):
                    escaped_ocr.append(f",{line}")
                else:
                    escaped_ocr.append(line)
            lines.extend(escaped_ocr)
            lines.append("#+END_EXAMPLE")
        else:
            lines.append("/[No OCR text recorded for this screenshot]/")
            
        lines.append("")

    log_path.write_text("\n".join(lines), encoding="utf-8")

```

### How this solves it:

* A line like `* Our Next Big Projects` becomes `, * Our Next Big Projects`.
* Org mode's font-lock and outline views will no longer recognize it as a level 1 headline.
* If you edit or copy out of the example block in Org, Org understands the `,` prefix as verbatim escaping.
